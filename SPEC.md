# gdpr-rag — Spec

End-to-end RAG over the GDPR with a compliance checker for privacy policies. Portfolio project: equal weight on pipeline depth (measured with evals) and product polish. Runs locally; the database is a local file, models are called through OpenRouter.

License: AGPL-3.0 (required by pymupdf4llm).

## Run (no Docker)

Prerequisites: `uv` and an OpenRouter key (in `.env` as `OPENROUTER_API_KEY`, or pasted on the settings page).

```
git clone … && cd gdpr-rag
uv run gdpr-rag ingest     # fetch GDPR, chunk, embed, index
uv run gdpr-rag serve      # http://localhost:8000
```

FastAPI serves the prebuilt frontend; Node is only needed for frontend development (`npm run dev`).
Each user brings their own OpenRouter key. (Claude subscription tokens were rejected: Anthropic's terms forbid routing Pro/Max credentials through third-party apps.)

## Stack

| Layer | Choice |
|---|---|
| Backend | Python, FastAPI, uv |
| LLM | ChatGPT Plus/Pro plan via Sign in with ChatGPT (OAuth + PKCE, Responses API): answers `gpt-6.1-sol`, reranking and follow-ups `gpt-6-luna`, both changeable in settings. Question generation and judging: `EVAL_MODEL`, `anthropic/claude-sonnet-5.5` via OpenRouter. Claude Haiku answers were dropped: 0.86 vs 0.98 faithfulness on the same retrieval |
| Embeddings | OpenRouter embeddings API, `google/gemini-embedding-2` (bake-off winner; ChatGPT plans can't embed, and the best local model reached only 0.82 recall@5) |
| Reranker | LLM rerank of the 30 fused candidates with the fast model, `gpt-6-luna` (the local tiny cross-encoder scored far worse) |
| Store | one SQLite file: sqlite-vec (vectors, one table per embedding model), FTS5 (BM25), app data (chats, documents, settings) |
| PDF parsing | pymupdf4llm; DOCX via python-docx; MD/TXT direct |
| Frontend | React + Vite + TypeScript, Astryx design system (`@astryxdesign/core`, neutral theme, system fonts: its Google Fonts import is dropped to keep the app local) |

Language: English only in v1.

## API key

- `.env` `OPENROUTER_API_KEY`, or a key field on the settings page (saved in the local SQLite file; the UI key wins over `.env`).
- After saving, the UI only shows a masked form (`sk-or-…66de`); the key is never returned by the API.
- The key is only ever sent to OpenRouter.

## Corpus

- GDPR from the EU Publications Office (same Official Journal text as EUR-Lex, CELEX 32016R0679; EUR-Lex itself serves scripts a bot challenge).
- One chunk per article paragraph (e.g. Art. 6(1)); paragraphs over 350 words are split per lettered point with the lead-in repeated. Metadata: chapter, article, paragraph, title.
- One chunk per recital.
- No article↔recital mapping (not published by EUR-Lex); retrieval surfaces recitals.
- EDPB guidelines: out of scope for now.

## Uploads

- PDF / DOCX / MD / TXT, max 20 MB, text PDFs only (scanned PDFs rejected with a clear message, no OCR).
- Chunked by heading, ~500-token cap, section path as metadata, `source=user`.
- Stored locally; deleting a document deletes its chunks.
- Upload page notice: document text is sent to the embedding and answering models via OpenRouter.

## Retrieval and answering

1. BM25 (FTS5) top 30 + vector top 30.
2. Reciprocal Rank Fusion (hand-written).
3. Rerank to top 6 (method from the bake-off).
4. The LLM answers citing chunk IDs `[c3]`; backend maps IDs to labels (`Art. 6(1)`, document + section) and drops citations to chunks that were not retrieved.
5. Nothing relevant retrieved → "Not found in sources", no guessing.

Chat scope toggle: GDPR / My documents / Both (default Both); citations show source type.

## Compliance check

- Input: an uploaded privacy policy.
- Checklist: Art. 13/14 transparency items (~14): controller identity, DPO contact, purposes, legal basis, legitimate interests, recipients, international transfers, retention period, data subject rights, consent withdrawal, right to complain to a supervisory authority, statutory/contractual requirement, automated decision-making, source of data (Art. 14).
- Per item: Covered / Partial / Missing / Not applicable (only when the policy itself says the case doesn't arise), quoted evidence from the policy, GDPR article basis, one-line fix.
- Quotes are verified verbatim against the document; Covered/Partial without a verifiable quote is downgraded to Missing.
- Export as Markdown.

## Evals

- **Retrieval golden set**: ~50 synthetic questions generated by `EVAL_MODEL` from sampled article chunks, no manual review. Safeguards: paraphrase-forced prompt (no copied phrases > 3 words, layperson wording), second pass drops ambiguous / unanswerable / near-duplicate questions, generated once and committed as `eval/golden.jsonl`. README labels it "synthetic, auto-filtered".
- **Retrieval bake-off**: recall@5, recall@10, MRR for 4 embedding models (`qwen/qwen3-embedding-8b`, `mongodb/voyage-4-large`, `google/gemini-embedding-2`, `openai/text-embedding-3-large`) × modes (BM25, vector, hybrid, hybrid + LLM rerank, hybrid + local rerank). Winners become defaults; the table goes in the README.
- **Answer eval** (local only): `EVAL_MODEL` judges faithfulness and citation correctness on the same set.
- **Compliance eval**: 3 synthetic privacy policies with planted gaps against the checklist; score = gaps flagged.
- Eval results page in the UI.

## UI

Screens: chat (streaming, inline citations opening the exact passage in a side panel), local chat history, document library, compliance report, settings (API key, model), eval results. No login. "Not legal advice" disclaimer.

Visual rules — pure white, minimal:

| Role | Hex | Contrast on white |
|---|---|---|
| Background | `#ffffff` | — |
| Text | `#171717` | 17.9:1 |
| Secondary text | `#6e6e73` | 5.1:1 |
| Hairline border | `#e5e5e5` | decorative |
| Hover / selected surface | `#fafafa` | — |

- No accent color; citations are underlined text; active state is black.
- System sans-serif stack, generous whitespace, narrow centered reading column.
- No shadows, gradients, or rounded cards; 1px hairlines only.
- Compliance statuses are text labels, not colored badges.

## CI (GitHub Actions)

ruff, pytest, frontend typecheck + build. Retrieval eval runs when the `OPENROUTER_API_KEY` repo secret exists (fails on regression below the committed baseline) and is skipped with a note otherwise, e.g. on fork PRs.
